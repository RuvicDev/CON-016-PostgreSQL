¿Qué es y para qué sirve?

El conector PostgreSQL permite que el agente de Ruvic acceda a tu base de datos en modo solo lectura: puede consultar información, pero nunca modificarla. Una vez configurado, puedes pedirle al agente cosas como:

  • “Genera un reporte con las ventas del último trimestre y envíalo por correo.”
  • “¿Cuántos clientes nuevos se registraron esta semana?”
  • “Revisa por qué este query está lento y proponme mejoras.”

Operaciones soportadas:

Operación Qué hace
db.list_tables Lista las tablas de la base de datos con su cantidad de filas
db.read Lee los datos de una tabla (con límite de filas)
db.stats Estadísticas de una tabla: filas, tamaño, columnas y tipos
db.explain Analiza el plan de ejecución de una consulta sin ejecutarla
Solo lectura, por diseño El conector abre todas las conexiones en modo de solo lectura. Aunque el agente lo intentara, la base de datos rechazaría cualquier escritura.

Prerrequisitos

  • Una base de datos PostgreSQL 12 o superior (en tu servidor, en la nube — RDS, Cloud SQL, Azure Database — o en Docker).
  • Acceso administrativo a la base de datos (rol con permiso para crear usuarios), solo durante la configuración inicial.
  • Acceso de red desde la plataforma Ruvic al servidor de base de datos (host y puerto alcanzables; regla de firewall o lista de IPs permitidas si aplica).
  • Los datos de conexión: host, puerto (por defecto 5432) y nombre de la base de datos.

Configuración en el fabricante

Vas a crear un usuario dedicado de solo lectura para Ruvic. No uses un usuario administrador ni el de tu aplicación: un usuario dedicado permite auditar la actividad del agente y limitar el acceso al mínimo.

  1. Conéctate a la base de datos como administrador.

    Usa psql u otra herramienta (pgAdmin, DBeaver) con un rol administrador:

    psql -h TU_HOST -p 5432 -U postgres -d TU_BASE_DE_DATOS
  2. Crea el usuario de solo lectura para Ruvic.

    Elige una contraseña fuerte (mínimo 16 caracteres, generada aleatoriamente) y guárdala: la usarás en el formulario de Ruvic (campo Contraseña).

    CREATE ROLE ruvic_reader LOGIN PASSWORD 'CAMBIA_ESTA_CONTRASEÑA';
  3. Otorga los permisos de lectura.

    Sobre la base de datos y los esquemas que quieras exponer al agente (el ejemplo usa public; repite para otros esquemas):

    GRANT CONNECT ON DATABASE tu_base_de_datos TO ruvic_reader;
GRANT USAGE ON SCHEMA public TO ruvic_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO ruvic_reader;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
    GRANT SELECT ON TABLES TO ruvic_reader;
    Nota La última instrucción hace que las tablas creadas en el futuro también sean legibles por Ruvic sin repetir el GRANT.
  4. Habilita el acceso de red desde Ruvic.

    Si tu PostgreSQL restringe conexiones por IP (habitual en producción), permite la IP de la plataforma Ruvic:

    • Servidor propio: agrega una línea en pg_hba.conf (ej. host tu_bd ruvic_reader IP_DE_RUVIC/32 scram-sha-256) y recarga la configuración (SELECT pg_reload_conf();).
    • AWS RDS / Cloud SQL / Azure: agrega la IP en el security group o en la lista de redes autorizadas de la consola del proveedor.
    [ Captura: regla de firewall / security group con la IP de Ruvic — reemplazar por assets/img/pgsql-firewall.png ]
  5. Verifica el usuario desde fuera del servidor.

    Desde una máquina distinta al servidor de BD (idealmente con salida de red similar a la de Ruvic):

    psql -h TU_HOST -p 5432 -U ruvic_reader -d tu_base_de_datos -c "SELECT 1"

    Si responde 1, el fabricante quedó listo. Anota estos valores para la siguiente sección: host, puerto, base de datos, usuario y contraseña.

Permisos requeridos

Principio de mínimo privilegio: el usuario de Ruvic solo necesita estos permisos. No otorgues roles de superusuario, escritura ni administración.

Permiso Para qué sirve
CONNECT Abrir la conexión a la base de datos
USAGE (por esquema) Acceder a los objetos del esquema
SELECT (por tabla o esquema) Leer datos (db.read), contar filas y calcular estadísticas (db.stats), planificar consultas (db.explain)

Las vistas de catálogo que usa el conector (pg_stat_user_tables, information_schema.columns, pg_total_relation_size) están disponibles para cualquier usuario autenticado sobre sus objetos visibles; no requieren permisos adicionales.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta PostgreSQL y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo del formulario Valor
Host Hostname o IP del servidor (ej. db.empresa.com)
Puerto 5432 (salvo configuración distinta)
Base de datos Nombre de la base de datos a consultar
Usuario ruvic_reader
Contraseña La contraseña del paso 2. Se guarda cifrada como secreto: la interfaz no volverá a mostrarla
Timeout de conexión Opcional; 10 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma se conectará a tu base de datos y confirmará que las credenciales y la red funcionan.

[ Captura: formulario del conector PostgreSQL en Settings → Conectores — reemplazar por assets/img/pgsql-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: “Conexión exitosa a tu-host:5432/tu_base”. La tarjeta del conector cambia a estado Configurado.

  2. Automatización mínima de prueba.

    Abre una conversación nueva con el agente y pídele: “Lista las tablas de la base de datos PostgreSQL y dime cuántas filas tiene cada una.” El agente debe responder con el listado real de tus tablas. Si lo hace, el conector quedó operativo de punta a punta.

Solución de problemas

Mensaje / síntoma Causa probable y solución
“Autenticación fallida: usuario o contraseña inválidos” Contraseña mal copiada o usuario inexistente. Reintenta el paso 2 de la sección 3 y vuelve a guardar el formulario (deja la contraseña vacía para conservar la anterior o escribe la nueva para reemplazarla).
“No se pudo conectar … (timeout)” La plataforma no alcanza el host/puerto. Revisa el paso 4 (firewall / security group / pg_hba.conf) y que el host no sea localhost (debe ser accesible desde Ruvic, no desde tu equipo).
“La base de datos 'X' no existe” Nombre de base de datos mal escrito en el formulario. Verifica con \l en psql.
El agente ve las tablas pero “permission denied” al leer una Falta el GRANT SELECT sobre esa tabla o esquema (tablas creadas antes del ALTER DEFAULT PRIVILEGES). Repite el paso 3 de la sección 3 para ese esquema.
El conector aparece “Sin configurar” tras guardar Algún campo obligatorio quedó vacío. Ábrelo de nuevo y completa host, puerto, base de datos, usuario y contraseña.

Preguntas frecuentes y notas de seguridad

¿El agente puede modificar o borrar datos?

No. El conector abre todas las conexiones en modo solo lectura y el usuario ruvic_reader solo tiene permiso SELECT. Hay dos barreras independientes.

¿Dónde queda guardada la contraseña?

Como secreto en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarla; solo indica “definida”. Para cambiarla, escribe una nueva en el formulario; para conservarla al editar otros campos, deja el campo vacío.

Rotación de credenciales

Recomendado cada 90 días o según tu política: cambia la contraseña en PostgreSQL (ALTER ROLE ruvic_reader PASSWORD '...'), actualízala en el formulario del conector y pulsa Probar conexión.

¿Qué hago si la contraseña se compromete?

  1. Cambia la contraseña en PostgreSQL de inmediato (ALTER ROLE … PASSWORD) o desactiva el usuario (ALTER ROLE ruvic_reader NOLOGIN).
  2. Revisa la actividad reciente del usuario en los logs del servidor.
  3. Actualiza la nueva contraseña en el formulario del conector.

¿Expiran las credenciales?

Por defecto no (usuario/contraseña de PostgreSQL no caducan solos). Si tu política exige expiración, configúrala con VALID UNTIL al crear el rol y programa la rotación antes de esa fecha.

Buenas prácticas Usa siempre un usuario dedicado y de solo lectura; restringe el acceso por IP; no expongas esquemas con datos sensibles que el agente no necesite; y evita compartir la contraseña por canales no seguros.
